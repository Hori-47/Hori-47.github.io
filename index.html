研究与工程

TensorRT 工程化

将 PI0.5 checkpoint 推进为可复用的 TensorRT 推理链路，并连接 Piper-X 真机完成端到端验证。

主要工作

  • 实现 Prefix / Denoise engine 构建、manifest 和 I/O contract 校验。
  • 提供 runtime smoke、parity 与 Piper no-publish / forward-only RTC 入口。
  • 围绕资源占用、延迟和反馈稳定性进行部署调试。

相关原理

把视觉编码与 flow-matching denoise 拆成可独立验证的 engine，通过固定 shape、dtype 和 action contract 降低模型部署的不确定性。

EVO-RL · HIL 数据闭环

把真实机器人 rollout、value 学习、ACP 视图和可恢复实验状态组织成一套可追踪流程。

主要工作

  • 固定 14D action/state、三路 RGB、30 FPS 的 piper_evorl_v1 契约。
  • 实现 no-publish HIL、feedback freshness、ACK、teleop takeover 和 round state machine。
  • 为 episode、manifest、derived label 和失败注入保留 provenance。

相关原理

通过人机协同和显式 outcome label 约束策略更新，把真机试验中的风险、反馈和数据质量转化为可复用的训练信号。

FASTER · Horizon-Aware Scheduling

面向流式 action chunk 和实时控制，补齐 Piper-X 服务端、客户端与非阻塞 refill worker。

主要工作

  • 实现 const / HAS schedule、同步 / 异步 / streaming 模式。
  • 加入 threaded newline-delimited TCP、fake loopback 和 policy processor 映射。
  • 用 scope、shape、protocol 与 safety tests 固化接口边界。

相关原理

依据未来动作有效期动态安排推理和发送时刻，减少 action chunk 过期造成的停顿，同时将通信与策略计算解耦。

Training-Time RTC for PI0.5

将随机延迟、clean prefix conditioning 和 future flow matching loss 引入训练阶段。

主要工作

  • 注册 rtc_pi05 策略并接入 train / eval / rollout。
  • 按有效 future token 做 per-sample loss normalization。

相关原理

训练时模拟推理延迟，让策略学习在已执行的 prefix 之后预测未来动作，从而提升流式控制下的连续性。
